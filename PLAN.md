# CSV Analytics Studio — архитектура и план разработки

## 1. Основа проекта

В `main` один начальный коммит с README. Локальный AGENTS.md прочитан, Git пока показывает его как неотслеживаемый файл. Код приложения, зависимости и CI ещё не настроены. Файлы в ходе планирования остались без изменений.

Первый релиз — одностраничное приложение на React, TypeScript в строгом режиме, Vite и Tailwind CSS. Пользователь может хранить несколько наборов данных и работать с одним активным набором. Согласованная цель первого релиза — CSV до **50 000 строк данных**. Импорт, обработка, хранение и экспорт происходят в браузере.

| Модуль | Ответственность |
|---|---|
| `src/app/` | Оболочка приложения, переключение режимов, общий React-контекст активного набора и пользовательских настроек |
| `src/data/` | Модель набора, импорт и экспорт через Papa Parse, определение типов и операции над строками |
| `src/analysis/` | Чистые функции для статистики, корреляций, пропусков, дубликатов, группировок и вычисляемых столбцов |
| `src/storage/` | Схема Dexie, загрузка наборов и транзакционная запись изменений |
| `src/features/` | Редактор и таблица на TanStack Table, панели анализа, Dashboard View и адаптер графиков |
| `src/i18n/` | Русский и английский словари i18next, локализация чисел, дат и сообщений |

Для визуализации достаточно **Plotly.js**. Он покрывает все семь типов графиков, включая Histogram, Box Plot и Heatmap. Recharts дублировал бы часть возможностей и потребовал бы второй интеграции для тем, размеров и интерактивности. Plotly.js загружается при первом открытии Dashboard View. [Документация Plotly.js](https://plotly.com/javascript/)

## 2. Модель данных, CSV и IndexedDB

- **`datasets`** хранит ID, имя, параметры импорта, ревизию и упорядоченное описание столбцов. У столбца есть стабильный ID, исходный заголовок, отображаемое имя, тип и, при необходимости, формула. **`rows`** хранит строки по составному ключу `[datasetId, rowId]`, исходный порядок и значения по ID столбца. Редактирование ячейки требует записи одной строки и обновления ревизии набора.
- **`charts`** хранит ID набора, тип графика, ссылки на ID столбцов, параметры и порядок карточки. **`preferences`** хранит язык, тему, последний набор и режим. Начальные значения — язык браузера с резервным английским и светлая тема. Схема Dexie версионируется с первой версии.
- Импорт сначала разбирает и проверяет файл, затем сохраняет метаданные и строки одной транзакцией. При ошибке записи интерфейс сохраняет последнюю подтверждённую версию и предлагает повторить действие. Изменения одного набора записываются последовательно. Проверка ревизии внутри транзакции обнаруживает конфликт с другой вкладкой и предлагает перечитать набор. [Транзакции Dexie](https://dexie.org/docs/Dexie/Dexie.transaction%28%29)
- **Импорт.** Papa Parse разбирает CSV как массивы строковых полей. В предпросмотре пользователь может исправить разделитель и указать, есть ли заголовки. Кодировка по умолчанию — UTF‑8, с ручным выбором Windows‑1251. Пустые и повторяющиеся заголовки получают различимые подписи в интерфейсе и сохраняют исходный текст. При разной длине записей дополнительные поля получают отдельные столбцы, отсутствующие значения обозначаются `null`, а предпросмотр сообщает о расхождениях. При повреждённых кавычках импорт останавливается с указанием записи. [Документация Papa Parse](https://www.papaparse.com/docs)
- **Типы.** Проверять все непустые значения столбца. Определять `number` для конечных десятичных чисел с точкой и безопасных целых, `boolean` для `true` и `false`, `date` для корректных дат `YYYY-MM-DD`. Пустые и смешанные столбцы, коды с ведущими нулями, неоднозначные даты и целые вне безопасного диапазона остаются `text`. Для аналитики пустая строка, строка из пробелов и `null` считаются пропусками, при этом импортированный текст сохраняется. Пользователь может выбрать тип вручную и увидеть число несовместимых значений. Последующие правки сохраняют выбранный тип.
- **Экспорт.** По умолчанию выгружать весь текущий набор в исходном порядке, включая явные правки и вычисляемые значения. Экспорт результата поиска и фильтрации — отдельное действие с текущей сортировкой. Сохранять текст исходных полей, корректно экранировать кавычки и переносы строк. По умолчанию включить защиту от интерпретации CSV-ячеек как формул в табличных редакторах и явно обозначить эту настройку, поскольку она добавляет апостроф к соответствующим значениям. [Параметры экспорта Papa Parse](https://www.papaparse.com/docs#unparse-config-default)

## 3. Общий поток данных и аналитика

**IndexedDB → активный набор в React → вычисляемые столбцы → поиск и фильтры → таблица, статистика и графики.** Таблица дополнительно сортирует результат и делит его на страницы. Line использует текущий порядок сортировки. Оба режима показывают один и тот же набор прошедших фильтр строк, даже если в таблице открыта только одна страница. Поиск и фильтры сохраняются при переключении режимов. После подтверждённой правки производные результаты обновляются из новой ревизии набора.

- **Качество данных.** Показать число пропусков по столбцам и точные дубликаты по всем исходным полям, с возможностью отфильтровать соответствующие строки. Очистка ячейки, удаление строки и удаление повторов требуют явного действия. При удалении повторов сохранять первую запись в исходном порядке.
- **Статистика.** `count` считает валидные непустые значения. Mean, median, min, max и стандартное отклонение рассчитываются по валидным числовым значениям. Для стандартного отклонения использовать выборочную формулу с `n − 1`. Для корреляции использовать коэффициент Пирсона по строкам, где валидны оба значения. При недостатке наблюдений или нулевой дисперсии в корреляции показывать «нет значения».
- **Преобразования.** Группировка по одному или нескольким столбцам формирует отдельную сводку. Поддержать число строк, сумму, среднее, минимум и максимум. Пропуски в ключах образуют отдельную группу. Вычисляемый столбец задаётся согласованным конструктором из двух числовых столбцов или констант и одной операции `+`, `−`, `×`, `÷`. Хранить описание формулы и вычислять результат при чтении. Пропуски, несовместимые операнды и деление на ноль дают пустой результат. В первом релизе операнды ссылаются на исходные столбцы, поэтому циклы невозможны.
- **Dashboard View.** Каждая карточка имеет собственные поля и настройки. Line, Bar и Scatter используют выбранные оси. Pie группирует по категории и показывает число строк или сумму неотрицательных значений. Histogram и Box Plot работают по числовому столбцу, а Correlation Heatmap использует ту же матрицу Пирсона, что и панель анализа. Несколько карточек автоматически размещаются в адаптивной CSS-сетке. Некорректная конфигурация остаётся доступной для исправления и показывает причину, например смену типа столбца.

## 4. Этапы и критерии готовности

| Этап | Проверяемый результат |
|---|---|
| **1. Каркас** | Открываются оба режима и пустое состояние. Русский и английский интерфейсы и обе темы переключаются и восстанавливаются после перезагрузки. В CI проходят `npm ci`, проверка типов, Vitest и сборка Vite. |
| **2. Полный цикл CSV** | CSV можно предварительно просмотреть, импортировать, отредактировать, восстановить из IndexedDB и экспортировать. Тесты покрывают кавычки, переносы, кодировки, повторяющиеся заголовки, неодинаковую ширину строк и сохранение `00123`. Ошибка импорта или записи оставляет ранее сохранённый набор доступным. |
| **3. Таблица и аналитика** | Поиск, сортировка, фильтры, пропуски и дубликаты проверены на контрольных данных. Vitest сверяет статистику, корреляции, группировки и формулы с ожидаемыми результатами, включая пустой набор, одно наблюдение, постоянные столбцы и деление на ноль. |
| **4. Dashboard** | Все семь графиков строятся на контрольных данных. Несколько карточек можно независимо настроить, удалить и восстановить после перезагрузки. В браузере проверить, что правка и фильтр дают согласованный результат в таблице, статистике и графиках, а сетка работает на мобильной и широкой раскладках. |
| **5. Подготовка публикации** | Проверить production-сборку под `/csv-analytics-studio/`, включая загрузку модуля графиков, восстановление IndexedDB и отсутствие сетевой передачи CSV. Подготовить GitHub Actions для Pages и документацию на русском и английском с описанием локального хранения, ограничений и использования Codex. Публикация — после явного одобрения. [Руководство Vite по GitHub Pages](https://vite.dev/guide/static-deploy.html#github-pages) |

## 5. Риски и меры

- **Объём файла и задержки.** Держать в памяти только активный набор, выводить таблицу постранично и разбирать файл в worker Papa Parse. До релиза проверить импорт, фильтрацию, расчёт корреляций и открытие нескольких графиков на CSV из 50 000 строк × 20 столбцов. Зафиксировать время и окружение. Если профилирование выявит блокировку интерфейса расчётами, вынести тяжёлые расчёты в Web Worker.
- **Квота и очистка браузерного хранилища.** Проверить отказ записи и восстановление после перезагрузки в реальном браузере. При недоступности IndexedDB явно показать статус сохранения и оставить экспорт доступным для открытого набора.
- **Числовая точность и расхождения между представлениями.** Хранить исходный текст отдельно от его интерпретации, проверять пограничные значения тестами и подавать в статистику, сводки и графики один отфильтрованный набор. Для Correlation Heatmap использовать готовую матрицу корреляций из модуля анализа.

# CSV Analytics Studio — окончательные архитектурные решения

### 1. IndexedDB — одна запись на строку

**Выбираем отдельные записи** с ключом `[datasetId, rowId]` и полем исходного порядка. Блоки уменьшают число записей и могут ускорить полную загрузку, но при правке одной ячейки пришлось бы прочитать и перезаписать весь блок. Для цели **50 000 × 20** начнём с построчного хранения и замерим импорт, загрузку и сохранение правки на контрольном CSV. Импорт записывает строки пакетно через `bulkPut` в одной транзакции с метаданными набора. [Документация Dexie](https://dexie.org/docs/Table/Table.bulkPut())

### 2. Графики — сокращаем отрисовку, считаем по всем строкам

Таблица, статистика и Dashboard используют общий результат фильтрации **до пагинации и сокращения точек**. Статистика, корреляции, группировки, интервалы гистограммы и квартили Box Plot рассчитываются по всем подходящим строкам. Для Line начальный лимит — 2 000 точек с сохранением локальных минимумов и максимумов в порядке серии. Для Scatter — 5 000 точек из воспроизводимой выборки. Карточка показывает «Отображено N из M точек». Bar и Pie агрегируют все подходящие строки и объединяют категории за пределами первых 30 по величине в «Остальные». Heatmap получает готовую матрицу Пирсона. Лимиты проверяем на наборе 50 000 × 20 с несколькими открытыми карточками Plotly.js. [Документация Plotly.js](https://plotly.com/javascript/)

### 3. Просмотр и изменения набора

- **Просмотр.** Поиск, фильтры, сортировка, пагинация, просмотр пропусков и дубликатов, группировка, переключение режимов и экспорт результата работают с производным представлением. Конфигурации графиков и пользовательские настройки сохраняются отдельно от набора.
- **Изменения.** Подтверждённые правки ячеек, удаление строк или дубликатов, смена типа и добавление вычисляемого столбца обновляют набор и его ревизию транзакционно. Фильтр «Дубликаты» показывает совпадения, а отдельное действие «Удалить дубликаты» показывает число удаляемых строк и требует подтверждения.

### 4. CSV-экспорт — явный выбор режима

По умолчанию включена **защита от формул**. Она добавляет апостроф к экспортируемым ячейкам и заголовкам, начинающимся с `=`, `+`, `-`, `@`, табуляции, перевода строки, возврата каретки или полноширинных вариантов этих знаков. Например, `=1+1` станет `'=1+1`, а `-42` станет `'-42`. Перед скачиванием показываем число изменяемых полей. Изменения применяются только к выгружаемому файлу. Режим **«Без защиты от формул»** сохраняет значения полей и при наличии таких значений требует подтвердить скачивание. Для обоих режимов доступны весь набор в исходном порядке и результат фильтрации в текущем порядке сортировки. [Papa Parse](https://www.papaparse.com/docs#unparse-config-default), [OWASP CSV Injection](https://owasp.org/www-community/attacks/CSV_Injection)

### Первая задача реализации

Собрать минимальный каркас **React + TypeScript strict + Vite + Tailwind**, подключить Vitest и настроить `base: '/csv-analytics-studio/'`. Критерий готовности — CI после `npm ci` выполняет проверку типов, тесты и сборку, а собранная оболочка открывается под нужным префиксом и переключает Data View и Dashboard View. Затем реализовать сквозной сценарий CSV → IndexedDB → таблица → правка → экспорт, после него аналитику, графики и проверку перед публикацией. [Руководство Vite по GitHub Pages](https://vite.dev/guide/static-deploy.html#github-pages)

На этапе планирования файлы остались без изменений, зависимости не устанавливались.
